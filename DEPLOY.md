# ZYREX — Render Deployment

## Recommended first deployment

1. Push this project to a GitHub repository.
2. In Render, create **New → Web Service** and connect the repository.
3. Use:
   - Runtime: Node
   - Build: `npm install`
   - Start: `npm start`
   - Health check: `/api/health`
4. Set `ADMIN_PASSWORD` to a strong password in Render Environment Variables.
5. `SESSION_SECRET` is generated by the included `render.yaml`.
6. Deploy and open the generated `onrender.com` URL.
7. Open `/game` for the 3D ZYREX game.

## WebSocket

The multiplayer server uses `/ws`. Render Web Services support WebSocket connections.

## Important persistence note

The current server stores users, profiles, leaderboard and social data as JSON files under `DATA_DIR`.
Render's normal filesystem is ephemeral. A free deployment is therefore suitable for testing, but saved server-side data can be lost after restart/redeploy.

For persistent production data, migrate these stores to Render Postgres/Key Value, or use a paid persistent disk mounted at `/opt/render/project/src/data`.

## Security

Do not commit `.env` or real passwords/secrets. The included `.gitignore` already ignores `.env` and `data/*.json`.

## Smoke test

After deployment:

- `GET /api/health` should return HTTP 200.
- `/` should load the existing ZYREX website.
- `/game` should load the game shell.
- Register/login should reach the API.
- Multiplayer should connect through `/ws` when the browser runtime and network permit it.
