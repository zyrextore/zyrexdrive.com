# ZYREX PHASE 71–100

## Phase 71–75 — Multiplayer foundation
- Authenticated room creation/list/join/leave
- Max 8 players per room
- Player heartbeat/presence TTL
- Reconnect-aware client state

## Phase 76–80 — Vehicle/player sync
- Client sends clamped vehicle transform/state
- Other players rendered as remote vehicle ghosts
- Smooth interpolation
- Ready/unready state

## Phase 81–85 — Lobby/social
- Room list and room ID
- Host handoff when host leaves
- In-room player roster
- Room chat with server-side length/sanitization limits

## Phase 86–90 — Shared-world foundation
- Periodic presence synchronization
- Shared room state suitable for future races/missions
- Online health endpoint

## Phase 91–95 — Online competition foundation
- Existing account + leaderboard APIs remain compatible
- Online room ready state can gate future multiplayer race start
- Server clamps transform values to reduce malformed client state

## Phase 96–100 — Resilience/polish
- Polling reconnect indicator
- Automatic heartbeat/refresh
- Leave-room cleanup and stale-player expiry
- Multiplayer UI and mobile-safe layout

### Important limitation
This phase uses HTTP polling rather than WebSocket because no new runtime dependency is introduced. It is an online multiplayer foundation/prototype, not authoritative multiplayer physics. A future WebSocket/WebRTC transport can replace polling without changing the room/player data model.
